# 交接规则（Handoff Rules）

交接文档是**一次工作的上下文快照**：让下一位（另一个人、另一个 AI、或明天的你）不看聊天记录就能接手继续干。本文规定何时写、怎么写、怎么接、怎么归档。

## 1. 何时必须写交接

出现以下任一情况，负责收尾的人 / AI 必须写一份交接文档：

| 触发条件 | 说明 |
| --- | --- |
| **会话收尾** | AI 会话结束前，或用户说"交接 / 收尾 / 总结一下留档" |
| **上下文将满** | AI 判断对话上下文即将耗尽，继续工作有丢失风险 |
| **换人 / 换模型** | 工作要从一个人（或模型）转给另一个人（或模型） |
| **切换工作线** | 当前工作未完成但要先去做别的事，超过半天不会回来 |
| **阻塞求助** | 卡住需要别人接手 / 拍板 |
| **里程碑** | 一个阶段性目标完成（如分支功能冻结、准备合并） |

以下情况**不必**写：单条命令级别的小改动、几分钟内闭环的小事（直接提交即可）。

## 2. 位置与命名

```text
docs/handoff/
├── README.md               # 索引（每次新增 / 归档交接后更新）
├── HANDOFF-RULES.md        # 本文件
├── HANDOFF-TEMPLATE.md     # 模板
├── 2026-10-21-xxx.md       # 活跃交接（按日期倒序排列）
└── archive/
    └── 2026-09-30-xxx.md   # 已归档交接
```

- 文件名：`YYYY-MM-DD-<slug>.md`。日期为**写交接当天**（ISO 格式）；`slug` 用小写英文短横线（或不超过 8 字的中文短词），概括本次工作，如 `playwright-smoke`、`拆分配置`。
- 同一天有多份交接：slug 保证不重复，必要时加序号 `-2`。
- 新交接放在 `docs/handoff/` 根下，**不要**直接放进 archive。

## 3. 写作规则

1. **自包含**：读者只看这一份文档 + 仓库文件就能接手。禁止出现"如上文所述 / 见聊天记录 / 老师你懂的"。
2. **事实优先**：只有实际验证过的事项才写进「已完成」；在做的写「进行中」；没碰的写「未完成」。三者严格分开，不许含糊。
3. **可执行的下一步**：每条 TODO 写到「哪个文件、改什么、跑什么命令、验收标准是什么」的粒度。
4. **决策必须带原因**：写清"为什么这么做"，防止接手者好心推翻；被推翻过的设计尤其要写。
5. **指向代码用符号**：写 `index.html · mountOps()` 而不是行号；写 commit hash 而不是"上次提交"。
6. **单一时间线**：一份交接覆盖一段工作；后续进展写**新**交接并在「关联文档」里链接前一份，形成交接链。不要在旧交接里大段续写。
7. **篇幅**：单份 ≤ 200 行。写不下的拆成多份或链接专题文档。
8. **安全**：不写密钥、令牌、个人信息。发现历史交接里有敏感内容立即上报并处理。

## 4. 接手流程（按顺序执行）

1. **读最新的交接**：去 `docs/handoff/README.md` 索引找最新一份，通读。
2. **读 `AGENTS.md`**：了解仓库约定与边界（特别是「边界（做之前先确认）」一节）。
3. **复跑验证清单**：按 `AGENTS.md` 的「验证清单」跑一遍，确认接手时代码处于文档描述的状态；不一致先记录差异再动手。
4. **认领**：在交接文档「元信息」表填入接手人，把状态从「🟡 待认领」改为「🟡 进行中」。
5. **开工**：按「下一步」逐条执行，做完一条勾一条。
6. **收尾**：工作结束（或再次触发第 1 节的条件）时写新交接；完全闭环的交接移入 `archive/` 并更新索引。

## 5. 归档规则

- 交接里的事项**全部闭环**，或已被更新的交接完整覆盖 → 移入 `docs/handoff/archive/`。
- 移动后在 `docs/handoff/README.md` 索引里把它挪到「已归档」表。
- 归档文件**内容不再修改**（历史快照，保持原样）；发现写错了在新交接里更正。

## 6. AI 特别约定

- **自动交接（用户 2026-10-21 授权，长期有效）**：AI 完成一个工作段落（收尾、会话将结束、切换工作线、里程碑）时，**自动**按模板写交接、提交、更新索引，不必等用户开口；写完把文件路径告诉用户。
- 用户主动说“交接 / 收尾 / 留档”时同样必写，不得省略。
- AI 判断上下文将满时，应**主动**提醒用户写交接，而不是硬撑到丢失。
- 写交接时必须真实反映验证状态：没跑过的验证项写「未验证」，不许写成「已通过」。
- 模型信息如实填写（模型名 / 会话），便于追溯。
