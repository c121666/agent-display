## 4. 关键决策与原因

| 决策 | 原因（为什么这么做） | 影响 / 注意 |
| --- | --- | --- |
| `data/` 加入 `.gitignore`，快照不入库 | AGENTS.md 规则 5「不写真实业务数据」优先于数据契约「默认随仓库提交」；快照含真实用量与成本 | 想留痕可本地自行提交；接手者不要把 `data/` 强行入库 |
| 请求四计数窗口 = 当日 | 与「今日成功率」同窗，口径统一 | 全部请求 = 今日 174 这类数字随日期重置 |
| `retried` 恒为 null、`failed` 只计日志可见错误 | 会话日志分不出重试链路；Codex 的失败请求不写 `token_count` 事件 | REQ 面板「重试成功」长期显示「—」属预期，不是 bug |
| 「当前聊天框」= 最近一个会话文件的合计 | 日志里没有"当前"概念，取最近会话是最近似 | 多项目并行时数值含该项目全部 agent 会话 |
| cost 只在当日记录**全部**带 cost 时才合计，否则 null | pi 有 cost、Claude/Codex 没有；半截账违反缺失态口径 | 混用 agent 时成本显示「—」属预期 |

## 7. 风险与已知问题

- `file://` 双击打开时 fetch 不到 `data/`，面板保持演示态 · 影响：双击看不到真数据 · 规避：本地静态服务预览（README「数据同步」一节有完整命令）。
- 本机 `python` 命令损坏（rc=49）而 `py` 正常 · 影响：照 AGENTS.md「常用命令」直接跑会失败 · 规避：一律用 `py`；README 新增的数据同步命令已写 `py`。
- tps 秒桶口径 = 请求完成时刻的输出 token 归入该秒 · 影响：长请求的输出会挤在一个秒桶里，与真实瞬时吞吐有偏差 · 升级时机：接入网关旁路（当前拍板不做）才有逐 token 时间线。
