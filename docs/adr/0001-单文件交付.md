# ADR 0001 · 单文件交付：不引入构建、框架与多文件拆分

| 项 | 值 |
| --- | --- |
| 状态 | 已接受 |
| 日期 | 2026-10-21 |
| 决策者 | 项目所有者（用户）+ AI 会话 |
| 关联 | [0002 Shadow DOM 隔离](./0002-Shadow-DOM-样式与-id-隔离.md)（单文件内的隔离手段） |

## 背景

大屏的使用场景是展厅、办公室电视、直播背景：拿一台电脑或小主机，双击打开就全屏跑，不装环境、不部署、不联网（除字体）。交付物必须是「拷一个文件过去就能用」。

同时项目由 AI（pi）高频协作开发，单文件形态天然有一个风险：文件长（约 900 行），AI 容易"顺手重构"拆成模块、引个框架、加个打包器，把交付形态破坏掉。

## 决策

- 交付物就是**一个 `index.html`**，HTML + CSS + JS 全在里面，`file://` 双击即可运行。
- **不引入**：构建工具（Vite / webpack…）、前端框架、npm 依赖、CDN 脚本。外部请求仅 Google Fonts（加载失败回退系统字体）。
- **不拆分文件**：代码再长也不拆 JS / CSS 文件。定位代码靠 `AGENTS.md` 的「index.html 结构地图」（区块 + 符号名，不用行号）。
- 该边界写进 `AGENTS.md`「边界」与 `.pi/APPEND_SYSTEM.md`，AI 动手前必须读到。

## 备选方案

| 方案 | 否决原因 |
| --- | --- |
| 多文件 + 打包器（Vite 等） | 需要 Node 环境与构建步骤，破坏"双击即用"；展厅机器上没法构建 |
| 原生多文件（多个 `<script src>`） | `file://` 下 CORS 限制多、拷贝要带一串文件，交付复杂度上升 |
| 引入轻量框架（Preact / Vue 运行时） | 大屏是 Canvas 绘制 + 少量 DOM，框架收益接近零，却引入依赖与 CDN |
| 每款看板一个 HTML 文件 | 分支已定位单看板（见交接与 CHANGELOG 3.1），多文件多看板是已放弃的方向 |

## 后果

**正面**

- 交付、部署、备份都只是一份文件；GitHub Pages 直接可用。
- 无供应链依赖（字体除外），无构建失败、版本不兼容这类问题。

**负面 / 需要习惯**

- 文件会持续增长（当前约 900 行 / 280 KB 量级），编辑要靠结构地图定位。
- 无法用模块化测试手段，验证靠 `AGENTS.md` 验证清单（`/skill:verify-dashboard`）。
- 复杂度若发生数量级暴涨（例如接入真实数据源、多看板复活），需要**重开 ADR 重新评估**本决策，而不是默默拆文件。
