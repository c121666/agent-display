# ADR 0003 · 全模拟数据：不接真实接口与鉴权

| 项 | 值 |
| --- | --- |
| 状态 | 已接受 |
| 日期 | 2026-10-21 |
| 决策者 | 项目所有者（用户）+ AI 会话 |
| 关联 | [0001 单文件交付](./0001-单文件交付.md)（无后端是单文件形态的前提） |

## 背景

大屏要"一直在动"：任务在派、智能体在干、指标在涨。但项目没有后端、没有真实 agent 平台、没有账单接口；使用场景（展厅 / 直播背景）也不允许出现数据停更、接口挂掉的尴尬。

## 决策

- 页面所有任务、指标、产出均为**模拟示例数据**，由 `index.html · mountOps()` 内置模拟器生成（`tasks` / `agents` / `wfs` 状态 + `step()` 每 900 ms 推进 + `renderAll()` 刷新）。
- 页面上保留**「示例数据」标注**，展示时如实说明，不冒充真实业务数据。
- **不接入**真实数据源、后端服务、鉴权；不写入任何密钥或真实业务数据（`AGENTS.md` 边界 + `.pi/APPEND_SYSTEM.md` 已固化）。
- 未来若接真实数据：按 `README.md`「接入真实数据的改造方向」替换状态初始化与推进逻辑，且**先重开 ADR 评估**，不悄悄混入。

## 备选方案

| 方案 | 否决原因 |
| --- | --- |
| 对接真实 agent / 账单 API | 当前没有任何真实接口；还要引入鉴权、轮询、错误处理，违反 0001/0003 的轻量前提 |
| 外置 JSON 数据文件 | 多一个交付文件，破坏单文件交付（0001）；`file://` 下 fetch 本地 JSON 有 CORS 问题 |
| 手动填数据的配置面板 | 增加使用复杂度，展厅场景没人去填；模拟器已满足"持续在动"的需求 |

## 后果

**正面**

- 任何环境打开都有完整演示效果，永不空屏、永不过期；无密钥泄露风险。

**负面 / 需要习惯**

- 数字不是业务真实值：对外展示、汇报时必须说明是示例数据，不能当真实指标引用。
- 模拟器逻辑（`step()`、随机数种子）与展示逻辑耦合在 `mountOps()` 内，接真实数据时需要做映射改造，工作量不小——这正是"先评估再动手"的原因。
