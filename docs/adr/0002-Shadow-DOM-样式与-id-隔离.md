# ADR 0002 · Shadow DOM 隔离：看板样式与 id 作用域

| 项 | 值 |
| --- | --- |
| 状态 | 已接受 |
| 日期 | 2026-10-21 |
| 决策者 | 项目所有者（用户）+ AI 会话 |
| 关联 | [0001 单文件交付](./0001-单文件交付.md)（单文件内的隔离手段） |

## 背景

看板的样式类名和元素 id 都很简单直接（`.app`、`.btn`、`#clock`、`#s0`…），在外层文档里直接用很容易互相污染。本项目从 v3 多主题系列版沿用了「每个看板一块独立 Shadow DOM」的挂载方式：外壳只负责挂载，看板活在自己的影子树里。分支精简为单看板后，这个机制被保留。

## 决策

- 看板挂在 `<div id="host-ops">` 的 **Shadow DOM**（`attachShadow({mode:'open'})`）里，内容由 `<template id="tpl-ops">` 克隆进入。
- 看板样式写在模板内的 `<style>`：选择器用 **`:host` / `:host([data-theme=...])`**，不用 `:root`。
- 看板 JS 里查询元素一律用 **`SR.querySelector`**（影子树作用域）；id 只在影子树内唯一（当前 JS 引用 23 个 id）。
- 外壳样式（`.th-host` 等）留在文档级 `<style>`，与看板样式互不感知。
- id 增删必须两边同步，`/skill:verify-dashboard` 的 `scripts/check.py` 自动交叉核对。

## 备选方案

| 方案 | 否决原因 |
| --- | --- |
| 普通 DOM + 类名前缀（`.ops-btn`） | 靠纪律防冲突，AI 批量改样式时容易漏前缀；id 同名冲突无兜底 |
| iframe 嵌套 | 通信麻烦、全屏/自适应复杂化，`file://` 下还有额外限制 |
| CSS-in-JS / 运行时注入 | 与「无框架、无构建」的 0001 直接冲突 |

## 后果

**正面**

- 看板与外壳样式天然隔离，改一边不会串到另一边；批量改样式安全。
- 保留了未来再加看板的挂载方式（每块一个影子树），但**当前不打算加**（见 CHANGELOG 3.1 与交接）。

**负面 / 需要习惯**

- 调试时要在 DevTools 里展开 shadow root；`document.getElementById` 拿不到看板元素，必须走 `SR`。
- 全屏、`prefers-color-scheme` 等少数能力要按 Shadow DOM 的规则写（`:host` 媒体查询、事件穿透等）。
- id 同步是硬约束，改 id 一定要跑自动检查。
