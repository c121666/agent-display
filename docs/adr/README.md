# ADR · 架构决策记录

记录本项目的重大技术决策：为什么这么做、否掉了什么、有什么后果。目的是防止接手者（人或 AI）好心推翻已经想清楚的设计。

## 规则

1. **编号递增、文件名 `NNNN-标题.md`**，四位数字补零，不复用编号。
2. **状态口径**：提议中 → 已接受 → 已废弃（被新 ADR 取代时写明取代关系）。只增不删，废弃的保留原文。
3. **改主意 = 写新 ADR**，不要改旧 ADR 的决策内容；新 ADR 里写「取代 000X」。
4. 决策与代码冲突时，以代码现状为准，并尽快补/修 ADR。
5. 每篇必须包含：状态、日期、背景、决策、备选方案（含否决原因）、后果（正负面都写）。
