# 个人看板 · 数字汇报（状态展示）需求

> 来源：`core-features.md`，仅保留**数字汇报 / 状态展示**部分。
> 定位：一块只读的数据看板——只看汇总数字、状态和趋势，不做任何操作。

---

## 一、原则（保持不变）

1. **纯只读**：只读项目投递数据，不写任何内容。
2. **本机直读**：依赖读 `package.json` / `pom.xml`，提交读本地 `.git`；不联网、不执行命令。
3. **缺数据如实显示**：没写 / 没交 / 未跑 / 过期分开标注，不补 0、不猜 1。
4. **不做**：设置、备份恢复、项目登记编辑、看板拖拽、记录编辑、原型对照页、深色主题、全局搜索等一切非展示功能。

---

## 二、页面（1 个总览 + 1 个图表页即可）

### 1. 状态总览（首屏）

* **健康度总览**：每个项目一张卡——健康度、整体进度、分端进度、最近投递时间、依赖 / 技术栈标签。
* **待处理计数**：逾期、待交接、阻塞、收集未整理、满 3 次待优化、无合规投递、测试失败、回归未跑——每项一个数字 + 状态色。
* **投递异常计数**：校验失败、孤儿条目、过期投递。
* **最近动态**：最近的决策、日报、问题条目（只读列表，可省略）。

### 2. 图表 / 汇总数字

* **活动热力图**：按项目、按天的提交与日报动静。
* **每日 git 提交数**：每天各仓库提交数（供热力图与近 7 天活跃展示）。
* **每周吞吐**：每周完成任务数。
* **问题复发时间线**：近 90 天，每个签名一行，标出复发次数（满 3 次标为待优化）。
* **测试通过率**：各模块（单元 / 集成 / E2E）最近结果、通过率数字与趋势。

### 3. 项目数字明细（只读，点项目卡展开）

* **进度**：Burn Up、累积流图、周期时间分布、Roadmap。
* **任务**：八列各列数量（收集 / 待排 / 待办 / 开展 / 测试 / 交接 / 复核 / 完成）。
* **提交**：仓库分支状态（领先 / 落后）、当日提交数与行数。
* **计数**：问题数、文档数、未闭环任务数。

---

## 三、砍掉的内容

| 砍掉 | 说明 |
|---|---|
| 设置 / 备份 / 恢复 | 全部不要 |
| 项目登记（新建 / 编辑 / 归档） | 只留展示，配置可先写死或用现成数据源 |
| 看板交互（筛选、浮层详情、拖拽） | 只展示数字，不做交互 |
| 记录页（文档 / 日报 / 问题编辑） | 只保留计数与最近条目 |
| 原型对照 `/next/*` | 不要 |
| 导航五页 | 收敛为「总览 + 图表」两块 |

---

## 四、优先级建议

| 优先级 | 内容 |
|---|---|
| P0 | 健康度卡 + 待处理计数（首屏状态一眼看清） |
| P1 | 活动热力图 + 每日提交数 + 每周吞吐 |
| P2 | 问题复发时间线 + 测试通过率 |
| P3 | 项目数字明细（Burn Up / 累积流 / 提交统计等） |
