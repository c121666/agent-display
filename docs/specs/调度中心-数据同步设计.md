# 调度中心 · 数据同步设计（含 token 统计）

> 模块：`docs/specs/` · 状态：已拍板（2026-10-22，结论见第 8 节）· 日期：2026-10-22
> 上游参考：cc-switch v4.0「用量统计」（`farion1231/cc-switch`，`src-tauri/src/proxy/usage/`、`database/dao/usage_rollup.rs`、`docs/user-manual/zh/4-proxy/4.4-usage.md`）、magpie（`yetone/magpie`，`docs/reference.md` 的 usage 章节，2026-10-22 取 main 分支）
> 边界：看板侧仍是单文件 `index.html` + 模拟数据；本文只设计**数据怎么流进来**。接入真实采集器属于"开发侧推送"，看板只读不回写，不引后端、不引鉴权（见 `docs/adr/0003-全模拟数据.md`）。

## 1. 背景与目标

调度中心大屏的数字目前全部由 `index.html · step()` 模拟器生成。本设计定义「真实数据 → 大屏」的同步管道与 token 统计口径，让未来采集器（skill / 脚本）照着推数据，看板侧逐步替换模拟数据。

目标：

1. 同步管道**沿用《数字汇报-数据契约》的推快照模式**（全量快照、原子写、缺失态口径），不发明第二套机制。
2. token 统计口径参照 cc-switch / magpie 的成熟做法，字段一次定准，避免来回改契约。
3. 看板改动最小：只在消费端把模拟数据源换成快照数据源，渲染层不动。

## 2. 总体架构：三段式

```text
采集（开发侧）                快照（data/）              消费（看板侧）
┌─────────────────┐   原子写   ┌──────────────┐  fetch   ┌──────────────┐
│ 会话日志解析      │ ───────→ │ data/<id>.json│ ──────→ │ index.html   │
│ （rollup 聚合）   │  全量快照  │ （只增不回写） │  轮询     │ mountOps()   │
└─────────────────┘           └──────────────┘          └──────────────┘
```

| 段 | 谁负责 | 约定 |
| --- | --- | --- |
| 采集 | 项目里的 skill / 采集器脚本（看板仓库之外） | 按第 4 节字段产出 usage 记录并聚合 |
| 快照 | 同上 | 写 `data/<project-id>.json`，全量覆盖、先写 `.tmp` 再改名（原子写），规则见《数字汇报-数据契约》总则 |
| 消费 | `index.html` | 扫 `data/*.json` 轮询刷新（建议 60s）；文件缺失 / 字段缺失按契约第 4 节「缺失态口径」渲染，**禁止补 0** |

时钟、幂等、`schemaVersion` 演进、48 小时过期角标，全部沿用《数字汇报-数据契约》第 1、3、4 节，此处不重复。

## 3. token 统计设计（参考 cc-switch / magpie）

### 3.1 采集路线：会话日志解析（唯一）

2026-10-22 拍板：**只做一条采集路线**，双路线不必要。

| 项 | 内容 |
| --- | --- |
| 参照 | cc-switch「CLI 会话日志」扫描（`services/session_usage_*.rs`） |
| 原理 | 定期扫描各 agent 本地会话 JSONL（Claude Code `~/.claude/`、Codex `~/.codex/sessions/` 等），解析 usage 字段 |
| 优点 | 零侵入、不用改 agent 配置、开箱即得 |
| 已知限制 | 分不出具体供应商（cc-switch 也标注「{应用} · 会话日志」）；字段受各 agent 日志格式限制，缺的置 null |
| 不选网关旁路的原因 | 本地网关 / 代理旁路（magpie 的做法）更准，但要部署、要让流量绕道，P1 日志字段够用就先不上（YAGNI）；将来要精确到缓存细分 / 首 token 延迟时再评估 |

模型名归一化（cc-switch 做法）：采集侧统一成 `provider/model` 再入账，保证定价与聚合一致。

### 3.2 计量口径（一次定准）

**请求计数**（参照 magpie "Requests and failures"）：一次请求只按最终结局计一次——

| 概念 | 口径 | 对应看板「请求 REQ」标签 |
| --- | --- | --- |
| 全部请求 | 本轮请求总数 | 全部请求 |
| 成功 | 一次成功即答 | 成功 |
| 失败 | agent 最终拿到错误 | 失败 |
| 重试成功 | 首次失败、后续重试（换账号/换模型）答上 | 重试成功（**不算失败**） |
| 缓存命中率 | `cache_read_tokens / input_tokens` | 缓存命中率 |
| 今日成功率 | 当日 `成功+重试成功 / 全部` | 今日成功率 |

**吞吐 TPS**（2026-10-22 拍板）：面板滚动图取**每秒输出 token 数**（按 1 秒桶求和），大数字 = 最近一个完整秒；峰值 / 均值取近 30 秒。并发请求各桶直接求和（大屏展示总吞吐，不做 magpie 的「首 token 后速度 / 并发不叠加」修正）。

**用量 USE**：输入 / 输出 / 缓存读 / 缓存写（P1 先合并计）/ 调用次数。不单列推理 token（`reasoning_tokens`，2026-10-22 拍板砍掉：各 agent 日志支持度不一，且它已包含在输出 token 里）。

### 3.3 记录与聚合

**原始记录**（per-request，采集器内部留存，不进快照）：

```text
ts · agent · provider · model · account_key_fingerprint（只存指纹）
input_tokens · output_tokens · cache_read_tokens · cache_write_tokens
calls · outcome(ok|fail|retried) · cost · duration_ms
```

不存密钥原文、不存提示词与回复（magpie 隐私口径：只留计数与指纹）。

**聚合 rollup**（进快照的只有聚合结果）：

| 维度 | 参照 | 用途 |
| --- | --- | --- |
| 秒桶（近 30×1s） | — | TPS 滚动图 |
| 小时桶（近 24h） | cc-switch `usage_rollup` | 吞吐 / 请求趋势 |
| 天桶（近 90d） | `magpie usage today/7d/30d` | 「当天消耗 TODAY」、历史回看 |
| 模型 / agent | cc-switch 按供应商、模型、应用筛选 | 分摊与排行（P2） |

### 3.4 计费与配额（可选，P2）

- **价格表本地化**（magpie 做法）：`provider/model → 输入价 / 输出价 / 缓存读价 / 缓存写价`，可自定义覆盖；`cost = Σ tokens × 单价`。价格表归采集器维护，看板只显示 `cost`。**币种：美元**（2026-10-22 拍板，不做双显）。
- **配额窗口**（cc-switch 2.5 / magpie quota）：订阅类账户展示「剩余 x% + 重置倒计时」，低于 10% 加深提示。数据由采集器查 / 算，缺失显示「未采集」。

### 3.5 同步节奏（参照 cc-switch 用量页）

| 项 | 约定 |
| --- | --- |
| 常规 | 采集器启动扫一次，之后后台每 10 分钟扫一次 |
| 手动 | 采集器提供「立即同步」（快照 `updatedAt` 即上次同步时间，看板可显示） |
| 快照推送 | 每次有意义的进展后 + 每天收尾至少一次（同数据契约第 3 节） |
| 幂等 | 重复扫描同一批日志不得重复计数（按请求唯一 id / 文件偏移去重） |

## 4. 快照契约扩展：`tokens` 节（schemaVersion 2 草案）

在《数字汇报-数据契约》顶层结构中新增 `tokens` 节（其余节不动；`schemaVersion` 升 `2`，看板对不认识的节忽略）：

```json
"tokens": {
  "lastSync": "2026-10-22T18:00:00+08:00",    // 采集器上次同步时间
  "tps": { "now": 128, "peak30s": 210, "avg30s": 96, "series": [112, 96, ...] },  // series 近 30 秒每秒输出 token
  "requests": {
    "total": 128, "ok": 121, "failed": 4, "retried": 3,
    "cacheHitRate": 0.63, "successRateToday": 0.945
  },
  "session":  { "input": 12400, "output": 8100, "cacheRead": 6200 },   // 当前聊天框
  "today":    { "input": 186000, "output": 92000, "cacheRead": 176000, "cost": 4.28 },  // cost 美元
  "quota": [ { "account": "claude-plan", "remainingPct": 62, "resetAt": "...", "note": "5 小时窗" } ]
}
```

每个数值字段允许 `null`（= 未采集）；整节省略 = 未接入。**禁止补 0**，口径同数据契约第 4 节。注意区分：**当日无记录 = 真实 0**（采集器扫过、确实没请求），不是 null；`cacheHitRate` / `successRateToday` 分母为 0 时置 null（比值无意义，不算 0%）。

### 4.1 热力图数据源（2026-10-22 二次定稿：「近 60 天」日期视图）

热力图不设独立数据节，直接用 `repos[].daily` 按日期合计提交数（上一版「按时段（星期×小时）」的 `heat` 分桶节已**废弃删除**）。视图形态（用户定）：

- 行 = 周一~周五（固定 5 排，周六周日去掉）；列 = 近 60 天窗口内的**工作日**（左旧 → 右新），每根日期列落在它所属星期的行上。
- 色阶 = 当日提交数分档 1/3/6/10；无提交的列 = 真实 0（浅空格）；快照无 `repos` 节 = 未接入（全虚线格）。
- 右上标日期范围（MM-DD ~ MM-DD），下方「最忙: MM-DD · N 次提交」。

另：`tokens.today.byHour` = 当天 24 小时消耗（输入+输出），USE 标签柱状图取 08/09/10/11/14/15/16/17 八根（工作时段，12-14 午休不计柱）；「当前聊天框」口径废弃（2026-10-22 用户定）。

## 5. 看板映射（`index.html · monShow()` 三标签）

| 面板元素 | 快照字段 |
| --- | --- |
| TPS 大数字 / 滚动柱 / 峰值 / 均值 | `tokens.tps.now` / `series` / `peak30s` / `avg30s` |
| REQ 四块计数 | `tokens.requests.{total,ok,failed,retried}` |
| REQ 缓存命中率 / 今日成功率 | `requests.cacheHitRate` / `successRateToday` |
| USE 柱状图 / 当天消耗合计 | `tokens.today.byHour`（取 08/09/10/11/14/15/16/17 八根）/ `tokens.today.input+output` |
| USE 当天明细 | `tokens.today.*` |
| 热力图（近 60 天） | `repos[].daily[].commits`（按日期合计） | 行固定周一~周五 5 排、列 = 60 天窗口内工作日（2026-10-22 二次定稿） |

面板右上「auto 10s」旁可补 `lastSync`（P2）。渲染层不变，只换数据源（`step()` 生成 → 快照读取）。

## 6. 隐私与安全

- 采集范围由**用户显式勾选**（2026-10-22 定）：`tools/collect_tokens.py --scan` 只列候选（读会话文件头的 cwd），勾选入口 = 看板「设置」浮层（复制采集命令）或 `--project-dir`；未勾选的项目不解析会话内容，不做全盘扫描；勾选清单存 `data/_projects.local.json`（不入库）。
- 只同步**聚合计数**与**账户指纹**；密钥原文、提示词、回复一律不出采集器。
- 快照随仓库提交前自查无敏感信息；`data/` 可 `.gitignore`，看板不关心。
- 看板 `file://` 双击打开时 fetch 不到 `data/`：沿用数据契约第 9 节方案 A（本地静态服务）/ B（注入式 HTML）。

## 8. 拍板记录（2026-10-22）

| 问题 | 结论 | 原因 |
| --- | --- | --- |
| TPS 口径 | **每秒输出 token 总和**（非 magpie 的「首 token 后速度」） | 大屏看总吞吐，无诊断诉求，口径简单直观 |
| 成本币种 | **美元**，不做双显 | 简单统一 |
| 采集路线 | **只做会话日志解析一条**，不做网关旁路 | 双线路不必要；日志字段够用，网关部署成本高（YAGNI） |
| `reasoning_tokens` | **砍掉**，不单列 | 各 agent 日志支持度不一、口径不齐；它已包含在输出 token 里，大屏无「思考 vs 回答」拆分诉求 |
| 项目选择入口 | **看板「设置」浮层直接添加项目目录**（可多个，复制采集命令粘终端）；候选扫描与 `--pick` 均废弃 | 纯前端页面不能执行本机命令，执行必须落终端一条命令；用户要求「直接选目录，可以多选」，且不接受预扫描候选（2026-10-22） |
| 热力图形态 | **按时段视图**：星期 × 小时固定 7 排 × 24 列，不分前后端、不按仓库分行 | 2026-10-22 用户附样图定稿；旧「行成对 / 前后端 ≤2 对」规则废除 |
| 热力图形态（二次改版） | **近 60 天日期视图**：行 = 周一~周五（去周六周日），列 = 60 天窗口内工作日（左旧右新），每列落在所属星期行上 | 2026-10-22 用户定，推翻同日「按时段」版；`heat` 分桶节随之删除，直接用 `repos[].daily` |
| USE 标签 | 「当前聊天框」废除，改**当天消耗柱状图**（8 根工作时段柱 + 当天合计小行） | 2026-10-22 用户定；8 根 = 08/09/10/11/14/15/16/17（12-14 午休不计柱），合计仍为全天口径 |
