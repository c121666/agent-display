# 数字汇报看板 · 数据契约（JSON 格式规范）

> 模块：`docs/specs/` · 状态：设计稿（待评审）· 日期：2026-10-21
> 角色分工：**看板侧定义格式**（本文档），**开发侧按格式推送数据**（项目里的 skill / 采集器把 JSON 写进看板的 `data/` 目录）。看板只读，永不回写。

## 1. 总则

1. **全量快照，不推增量**：每次推送都是该项目的完整数据快照，直接覆盖旧文件。简单、可重放、不怕丢包。
2. **原子写入**：先写 `data/<project-id>.json.tmp`，再改名覆盖 `data/<project-id>.json`（防看板读到半截文件）。
3. **缺数据如实显示**：缺失必须走第 4 节的口径，**禁止补 0、禁止猜 1**。
4. **时间一律 ISO 8601 带时区**（`2026-10-21T18:00:00+08:00`）；日期字段用 `YYYY-MM-DD`；周用 ISO 周（`2026-W42`）。
5. **schema 演进靠 `schemaVersion`**：当前为 `1`。看板对不认识的字段忽略不报错；对不认识的 `schemaVersion` 显示「数据版本过新，请更新看板」。

## 2. 存储目录与文件布局

```text
data/
├── agent-display.json      # 每个项目一个文件，文件名 = project.id
├── another-project.json
└── _heartbeat.json         # （可选）推送器心跳，见 3.4
```

- 目录固定为看板仓库根下的 `data/`（与 `index.html` 平级）。
- 看板**自动发现**：扫描 `data/*.json`，有几份渲染几个项目；不需要登记表。
- 数据文件默认随仓库提交（留痕、可回溯）；嫌仓库变大可加入 `.gitignore`，看板不关心。

## 3. 推送约定

| 项 | 约定 |
| --- | --- |
| 频率 | 开发过程中随手推（每次有意义的进展后），以及每天收尾至少一次 |
| 方式 | 覆盖写 `data/<project-id>.json`（原子写，见总则 2） |
| 幂等 | 同一快照重复推送无副作用 |
| 时钟 | `updatedAt` 必须是推送时刻；看板以它判定「过期」（超过 48 小时未更新） |
| 校验 | 推送前建议跑看板仓库的 `tools/validate_data.py <文件>`（P0 交付物）；校验失败不要推送 |

### 3.1 推送方标识

`collector` 字段写明推送来源（如 `skill:push-progress@dev-project`），便于看板排查"这数据是谁塞的"。

## 4. 缺失态口径（产品灵魂，必须遵守）

| 形态 | 含义 | 看板渲染 |
| --- | --- | --- |
| **字段省略** | 该模块未接入 | 显示「未接入」，灰色 |
| **值为 `null`** | 已接入但未采集 / 未统计 | 显示「—」，灰色，注明「未采集」 |
| **空数组 `[]`** | 已接入、无记录 | 显示「0」或「无记录」，正常色 |
| **`updatedAt` 超 48 小时** | 数据过期 | 整卡打「过期」角标 + 虚线边框 |
| 数字 `0` | **必须是真实 0** | 正常显示 0，与其他状态严格区分 |

## 5. 顶层结构

```json
{
  "schemaVersion": 1,
  "project":   { ... },
  "health":    { ... },
  "progress":  { ... },
  "milestones": [ ... ],
  "tasks":     { ... },
  "burndown":  [ ... ],
  "cycleTime": [ ... ],
  "pending":   { ... },
  "deliveryIssues": { ... },
  "repos":     [ ... ],
  "activity":  [ ... ],
  "throughput":[ ... ],
  "issues":    [ ... ],
  "tests":     [ ... ],
  "counts":    { ... },
  "recent":    [ ... ]
}
```

`schemaVersion`、`project` 必填；其余节可省略（= 未接入）。

## 6. 分节字段定义

### 6.1 `project`（必填）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 项目标识，小写短横线，与文件名一致 |
| `name` | string | 展示名 |
| `path` | string \| null | 项目路径（展示用，可 null） |
| `stack` | string[] | 依赖 / 技术栈标签，如 `["vue3","java17"]`；可从 package.json / pom.xml 提取 |
| `updatedAt` | string(ISO) | 本快照推送时间 |
| `collector` | string | 推送方标识 |

### 6.2 `health`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `score` | number(0-100) \| null | 健康度评分；null = 未评估（**打分规则由推送方定义**，看板只展示） |
| `level` | `"ok" \| "warn" \| "bad" \| null` | 状态色；null = 未评估 |
| `note` | string \| null | 一句话说明（可选） |

### 6.3 `progress`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `overall` | number(0-1) \| null | 整体进度 |
| `byPlatform` | object \| null | 分端进度，键自由（`{"web":0.8,"ios":null}`），值同上 |

### 6.4 `milestones[]`（Roadmap 用，可空）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | 里程碑名 |
| `due` | string(date) \| null | 计划日期 |
| `done` | boolean | 是否完成 |
| `doneAt` | string(date) \| null | 完成日期 |

### 6.5 `tasks`（八列计数）

`collected`（收集）/ `queued`（待排）/ `todo`（待办）/ `doing`（开展）/ `testing`（测试）/ `handoff`（交接）/ `review`（复核）/ `done`（完成），每项 `number | null`。缺的写 null，**不写 0**。

### 6.6 `burndown[]`（Burn Up / 累积流共用，可空）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `date` | string(date) | 快照日 |
| `done` | number | 累积完成 |
| `total` | number | 累积总任务 |
| `wip` | number \| null | 在制（累积流图用） |

### 6.7 `cycleTime[]`（周期时间分布，可空）

`{ "task": "T-001", "days": 2.5, "finishedAt": "2026-10-18" }`，days 为小数天。

### 6.8 `pending`（待处理计数，P0 首屏）

| 字段 | 含义 |
| --- | --- |
| `overdue` | 逾期 |
| `handoffWait` | 待交接 |
| `blocked` | 阻塞 |
| `inboxUnsorted` | 收集未整理 |
| `recurrence3plus` | 满 3 次待优化 |
| `noDelivery` | 无合规投递 |
| `testFailed` | 测试失败 |
| `regressionNotRun` | 回归未跑 |

每项 `number | null`。注意 `pending` 整节省略 = 未接入，字段 null = 未采集。

### 6.9 `deliveryIssues`（投递异常计数）

`invalid`（校验失败）/ `orphan`（孤儿条目）/ `expired`（过期投递），`number | null`。

### 6.10 `repos[]`（git 提交数据）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | 仓库名 |
| `branch` | string \| null | 当前分支 |
| `ahead` / `behind` | number \| null | 相对远端领先 / 落后（无远端写 null） |
| `commitsToday` / `linesToday` | number \| null | 当日提交数 / 行数（±合计） |
| `daily[]` | array | 近 90 天：`{"date","commits","additions","deletions"}`，无提交的天**不写**（不是补 0） |

### 6.11 `activity[]`（热力图数据，近 90 天）

`{"date","commits","daily","note"}`：提交数、日报数、其他动静数。无动静的天不写。

### 6.12 `throughput[]`（每周吞吐）

`{"week": "2026-W42", "done": 7}`。无完成的周不写。

### 6.13 `issues[]`（问题复发时间线，按签名聚合）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `signature` | string | 问题签名（同根因归一类，推送方聚合） |
| `count` | number | 复发次数 |
| `firstSeen` | string(date) | 首次出现 |
| `occurrences` | string(date)[] | 每次出现日期 |
| `optimize` | boolean | 是否满 3 次待优化 |

### 6.14 `tests[]`（测试通过率）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `module` | string | 模块标识 |
| `kind` | `"单元" \| "集成" \| "E2E"` | 类型 |
| `passed` / `failed` / `skipped` | number \| null | 最近一次结果 |
| `lastRun` | string(ISO) \| null | 最近运行时间；null = 未跑 |
| `trend[]` | array | 近 30 天 `{"date","rate"}`（rate 0-1），未跑的天不写 |

### 6.15 `counts`

`problems` / `docs` / `openTasks`（未闭环任务），`number | null`。

### 6.16 `recent[]`（最近动态，可选，≤ 10 条）

`{"date","kind","text"}`，`kind` ∈ `decision`（决策）/ `daily`（日报）/ `issue`（问题）。

## 8. 看板模块 ↔ 数据字段映射（持续补充）

| 看板模块 | 数据来源 | 说明 |
| --- | --- | --- |
| 活动热力图 | `repos[].daily[].commits` | 行 = 仓库 / 模块（前端/后端）；色阶 = 当日提交次数分档（阈值待定，见台账问题日志） |

> 注：活动热力图的语义是**纯 git 提交次数**（2026-10-21 定），不做「提交 + 日报动静」合计。`activity[]`（含日报/动静）保留给「最近动态」类展示，不再作为热力图来源。

## 9. 双击 `file://` 打开的问题（预留方案）

浏览器双击 `index.html` 时无法 fetch 本地 `data/`（CORS）。预留两种模式，P0 先做模式 A：

- **模式 A（推荐）**：本地静态服务预览（`python -m http.server 8000`），看板 fetch `data/*.json`。个人看板在自己机器上常驻，开个服务无负担。
- **模式 B（可选，P3）**：采集器额外生成「内嵌数据版」HTML（把 JSON 注入页面），双击即看，适合拷给领导。
