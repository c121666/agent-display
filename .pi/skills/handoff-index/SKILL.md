# 交接索引与归档维护

规则出处：`docs/handoff/HANDOFF-RULES.md`（第 2 节命名、第 5 节归档）。本技能只管**索引与归档**；写交接内容用 `/handoff` 提示模板。

## 索引表格式

`docs/handoff/README.md` 里有两张表，格式不许改动：

**活跃交接（按日期倒序）**

```markdown
| 日期 | 文档 | 主题 | 状态 | 接手人 |
| --- | --- | --- | --- | --- |
| 2026-10-21 | [2026-10-21-docs-handoff.md](./2026-10-21-docs-handoff.md) | 项目管理文档体系建立 + 分支现状 | 🟡 待认领 | — |
```

**已归档**

```markdown
| 日期 | 文档 | 主题 | 归档原因 |
| --- | --- | --- | --- |
```

## 何时触发

1. **新增交接**：在「活跃交接」表顶部插入一行（日期倒序）。文档链接用相对路径 `./文件名`。
2. **状态变化**：被认领 / 进行中 / 受阻时，更新该行的「状态」「接手人」两列（状态口径：🟡 待认领 / 🟡 进行中 / 🟢 已完成 / 🔴 受阻）。
3. **归档**：满足归档条件（交接事项全部闭环，或已被更新的交接完整覆盖）时执行归档流程。

## 归档流程

1. 确认归档条件成立；拿不准就问用户，不要擅自归档。
2. `git mv docs/handoff/<文件>.md docs/handoff/archive/<文件>.md`。
3. 在 `docs/handoff/README.md` 里把该行从「活跃交接」移到「已归档」，归档原因写一行（如「事项全部闭环」）。
4. **归档后文件内容不再修改**（历史快照）；发现写错了在新交接里更正。

## 自检

- [ ] 索引表里的每个链接都能点开（文件存在、路径正确）
- [ ] 活跃交接按日期倒序排列
- [ ] `docs/handoff/` 根下没有已归档状态的文件残留
- [ ] 改动已按提交约定提交（`docs: 交接索引 …`）
